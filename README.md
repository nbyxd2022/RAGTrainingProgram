# RAGTrainingProgram

学习 Agent 的第一步：RAG。用 **Go + [Eino](https://github.com/cloudwego/eino)** 搭一个最小 RAG，逐步做检索对比实验与评测。

## 阶段计划

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 0. 骨架 | Go 工程 + Eino 依赖、`.env` 配置、17 篇中文语料 | 完成 |
| 1. 最小 RAG | 加载 → 切块 → 向量化 → 检索 → 生成（自写内存检索器，实现 Eino `Retriever` 接口） | 完成 |
| 2. 检索对比 | 2A 检索路线（纯向量 / 手写 BM25 / RRF 混合）；2B 切块策略（定长 / 重叠消融 / 按标题结构） | 完成 |
| 3. 评测 | 评测集定版（21 题，gold = 最小充分答案文本区间）+ 跨切块策略的 coverage@k 阶梯 @1/3/5/10/20 | 进行中 |
| 4. 进阶 | Eino 的 MultiQuery / Router、Parent 策略；把 RAG 接入 ReAct Agent | 待开始 |

## 快速开始

**1. 开通火山方舟 Ark**（约 5 分钟）

1. 注册[火山引擎](https://www.volcengine.com/)账号并完成实名认证
2. 进入[方舟控制台](https://console.volcengine.com/ark)，开通要用的豆包 chat 模型与 embedding 模型
3. 在「API Key 管理」中创建 API Key

> 控制台菜单名称以实际为准；模型 ID 或推理接入点 ID（ep-…）直接复制控制台里的填法。

**2. 配置**

```bat
copy .env.example .env
:: 编辑 .env，填入 ARK_API_KEY、ARK_CHAT_MODEL、ARK_EMBEDDING_MODEL
```

**3. 运行自检**

```bat
go run ./cmd/smoke
```

**4. 建索引**（一次性：切块 → 向量化，约 1 分钟；`-strategy` 选切块策略）

```bat
go run ./cmd/index                                   :: 默认 定长 500/50 → .data/vectors.gob
go run ./cmd/index -strategy heading -maxlen 800 -out .data/idx-heading.gob
go run ./cmd/index -strategy heading-nobc -maxlen 800 -out .data/idx-heading-nobc.gob
```

**5. 提问**

```bat
go run ./cmd/ask -q "什么是 RAG？"
```

**6. 检索对比**（纯向量 / BM25 / RRF 三路并排看排名与耗时；除向量路一次 API 调用外全本地）

```bat
go run ./cmd/compare -q "什么是 RAG？" [-k 5] [-n 20] [-idx .data/idx-heading.gob]
```

**7. 评测**（21 题 × 多切块策略 × 三条路线，看 coverage@k 阶梯 @1/@3/@5/@10/@20）

```bat
go run ./cmd/eval [-only 按标题]                     :: 需要先建好 5 个策略索引，见「阶段 2B」
```

## 阶段 2B：切块策略对比（2026-09-21，**旧尺子**：10 题 / gold = 基准窗口块 ID）

> 下表读数出自**旧尺子**（gold = 定长 500/50 的块 ID 窗口）。2C 换尺子后数字会变
> （见下节），本表保留作历史对照与"尺子偏置"的证据。

换切块策略后块 ID 全变，"按 ID 数命中"的 recall 没法跨策略比较。改用**与切块解耦的尺子**：
测试集的 gold 块 ID 经基准索引（定长 500/50）翻译成**源文档字符区间**，指标

```
coverage@k = |(前 k 条命中的区间并集) ∩ (gold 区间并集)| / |gold 区间并集|   （按 rune 字符数）
```

同一文档内先合并再求交（overlap 相邻块、多路命中都不重复计数）；漏召回的文档长度留在分母。
"校正"列再扣掉该策略自身**检索不到**的区域（按标题策略的标题行不在任何块的正文区间里）。

| 策略（块数） | 块长 最短/最长/平均 | 路线 | cov@5 | cov@10 | cov@20 | 校正@5 | 校正@10 | 校正@20 |

\* 含标题链前缀（【第一章… > 1.2 什么是 RAG】）；"无面包屑"版把标题链只写进 `meta["heading_path"]`，
正文不带前缀（最短块因此从 28 掉到 15 字），其余参数与按标题800 完全一致。正文上限即 800/500。10 题、候选池 top-20。

复现脚注：定长500/50 按块 ID 老尺子复核 = recall@5/10/20 0.683 / 0.883 / 1.000、MRR 0.702（2A 时为 0.704，差 0.002）。
噪声底：同一策略重跑，向量路逐题复现；RRF@5 出现过一次 0.788↔0.741 的翻转（一题名次在 5/6 间摆动），**差异 < 0.05 不要过度解读**。

**结论**

1. **重叠 50 是净收益，且机理清楚**。去掉重叠后 BM25 0.479→0.344@5、RRF 0.788→0.603@5。
   典型证据 Q3（"BM25 是怎么工作的？"）：gold 区域被 500/0 的边界劈成两半，三条路线都只
   拿到 0.40（另一半的块进不了 top-20）；500/50 下同一区域正好落在一整块里 → 1.00。
2. **结构感知切块在这套语料/测试集上没有赢**，但收益点和反作用力都找到了证据。
   - 收益：Q9（"RAG 和微调"）向量/RRF 0.36→0.67@5，整张对比表连同引言落进同一块；
     Q4（幻觉）三路 0.94（= 该策略可达上限 99%）；Q8（chunk_size/overlap）向量 0.55→0.71@5。
   - 反作用力 A · 面包屑前缀撞词：前缀把节标题写进了每块正文，同节所有块共享同一段前缀 →
     节内区分度下降、分数被压缩；其他文档的标题词也会被 BM25 当正文命中
     （Q7 的 BM25 top 全是【习题】【…缩放法则与局限性】这类"局限性"字面块）。
     Q1 的真答案被 05-llm-intro 四个带【… 1.2 什么是 RAG】前缀的块挤到 rank 6（0.5111 vs 0.5511）。
     （本轮已做消融量化，见结论 4）
   - 反作用力 B · 整代码块成一个单元：正文与代码分离后，以代码开头的块匹配不上自然语言问句，
     且 gold 区域跨两块 → 上限被锁死（Q3 = 0.43 恒定）。
   - 反作用力 C · gold 区域按基线窗口标注，跨自然边界时需要多块同时命中（Q1/Q8 在按标题500 下
     分别卡在 0.86 / 0.81）。
3. **块大小不是按标题策略落后的主因**：800 → 500 后向量@5 略升（0.583→0.667），但 BM25/RRF 反而更差
   （0.434→0.322、0.622→0.498）；块越小、区域跨块越多，上限被压得更死。
4. **面包屑消融：它是"用精排换召回"**（按标题800 vs 无面包屑，唯一变量 = 标题链是否拼进正文）：
   - **@5 显著受益**：向量校正 0.594→**0.709**（+0.115，同一套切法的配对差值，可信）。标本是 Q1——
     定义块此前被同节的【…1.2 什么是 RAG】前缀块挤到 rank 6，去掉前缀后直接回到 @5（0.00→0.98）。
   - **@10/@20 受损**：同节块失去共享的"话题标签"后更难被一起召回。BM25 最明显（@20 0.762→0.631；
     Q7"局限性"BM25@20 0.52→0.00、Q9"微调"0.67→0.21——标题文字本来是免费的关键词锚点）。
   - **解读**：面包屑把同节块绑成一簇，利在"整节都容易捞到"，弊在"簇内分不出谁最相关"。
     与定长基线的 @5 差距缩进噪声带（0.709 vs 0.691，不作超越宣称）。正确组合应是
     **"正文不带前缀保精排 + 命中后按 heading_path 把同节块聚合带上来"**——即阶段 4 的 Parent 策略，
     本轮拿到了它的必要性证据。

## 阶段 2C：评测集定版 —— 换尺子（2026-09-22）

**旧尺子的病根**：gold = 基准索引（定长 500/50）的块 ID，翻译回源文档后是一个**500 字窗口**，
里面混着 H1 标题行、代码注释、半句开头等非答案填充，形状又恰好等于定长块的形状 ——
于是"窗口形状"的策略拿免费分（300 字答案套在 500 字窗口里，定长块命中即 1.0）、
"自然边界"的策略反而吃亏（交全答案只得 0.8）。

**新尺子：gold = 最小充分答案文本**

- 一问 1~3 段**源文档字符区间**（`{doc,start,end,text}`），与切块策略彻底解耦；答案分散的题标多段，带回一段拿一段的分；
- 标注源文件 `eval/testset.spec.txt`（人读）→ `go run ./cmd/sections -emit` → `eval/testset.json`（机读）。
  编译期强制**每段引文与语料逐字一致、且全语料恰好命中一次**，标错直接报错；
- `cmd/eval` 启动时做 **gold 体检**（逐字比对语料切片），拦住语料/标注漂移；
- 题量 10 → **21 题**（覆盖 13 篇文档；标签分布 语义×12 / 字面×9 / 多段×7 / 表格×1 / 代码×1，平均每题 235 字 gold）；
- k 阶梯扩到 **@1/@3/@5/@10/@20**：cov@1 只看头名块，天然排名敏感，取代单独的 MRR 一列。

复现：`go run ./cmd/eval`（需先建好 5 个策略索引；本次 105 次 embedding 调用）。

**读数**

1. **排名重排，"定长最优"被削弱**（向量路）：
   - @5：按标题500 0.918 反超定长500/50 0.892 —— 差 0.026 ≈ 半道题，**在噪声带内，不作超越宣称**；
   - @1/@3：**无面包屑领先**（0.552 / 0.857，vs 定长 0.502 / 0.764）—— 头名精度上"整节一块"占优；
   - @10/@20：定长500/50 仍最高（0.965）；按标题策略 @20 到 1.000（整节粒度：晚到但全到）。
   - 旧尺子下按标题800 落后定长 0.108，新尺子缩到 0.048 —— 与"旧尺子给窗口形状发免费分"的判断一致。
2. **重叠 50 仍是净收益（新尺子上复现）**：定长500/50 vs 500/0，向量 @5 0.892 vs 0.838、@10 0.965 vs 0.944，BM25 @5 0.564 vs 0.532。
   标本 Q9（"如何评估检索效果"，gold 275 字）：500/0 全 k = 0.00（答案跨在块边界两侧）、500/50 = 1.00；Q18 同型（0.00 vs 0.27）。
3. **代码题上"边界落在哪"比策略名字更要紧**：Q14（Eino 代码，gold = 700 字两段）向量 @5 ——
   按标题500 = 1.00、定长500/0 = 1.00，而定长500/50 = 0.47、按标题800 = 0.00、无面包屑 = 0.00（@10 才 1.00）。
   gold 变精确后，"代码块被拦腰截断 / 以代码开头的块匹配不上自然语言问句"的代价被直接计分。
4. **面包屑的两面性复现**：Q1（"什么是 RAG"定义段）按标题800 = 0.00@5、其余策略 1.00（前缀撞词把定义块挤出 @5）；
   反过来 Q6（"RAG 的局限性"，63 字）**无面包屑全 k = 0.00**，带面包屑的都能在 @20 捞到（标题文字是免费关键词锚点）。
5. **校正列空转**：21 题里没有一题出现"可达 < 100%" —— gold 已不含标题行，而标题行是结构策略唯一的不可达区域，故校正 ≡ 原始。
   该列保留作探针（将来 gold 含标题、或某策略把正文挤出块区间时会立刻报警）。
6. **区分度集中在 7 道题**：@5 有差异的只有 Q1/Q6/Q9/Q10/Q14/Q15/Q18，其余 14 题五策略全 1.00。
   21 题 → 1 题 = 0.0476，**差值 < 0.10 基本是 2 道题以内的事**；补区分度（同义问法变体、多跳题、更小 gold）是评测集下一版的事。

## 目录结构

```
cmd/ask/          在线问答：检索 top-k + 基于资料生成（-q 问题、-k 条数）
cmd/compare/      检索对比：纯向量 / BM25 / RRF 混合三路并排看排名与耗时
cmd/eval/         检索评测：多切块策略 × 三路线 → coverage@k 阶梯（@1/@3/@5/@10/@20）
cmd/index/        离线建索引：语料 → 切块（-strategy fixed|heading）→ 向量化 → .data/*.gob
cmd/chunk/        切块观察：块数、长度分布、重叠/标题链效果；-grep 搜块
cmd/sections/     标注工具：节区间清单（-find 定位引文；-emit 把 spec 编译成 testset.json）
cmd/sim/          相似度自检：三句话验证 Cosine 方向是否正确
cmd/smoke/        API 冒烟测试：embedding + chat 连通性
corpus/           语料：17 篇中文公开文档，来源与许可见 corpus/SOURCES.md
eval/             评测数据：testset.spec.txt（人读标注源）+ testset.json（编译产物，含源文档区间）
internal/config/  环境配置加载（.env / 环境变量）
internal/eval/    评测：测试集加载（区间 gold）+ CoverageAtK（区间并集求交）+ recall@k/RR（库函数）
internal/llm/     Ark chat / embedding 适配器封装
internal/rag/     RAG 核心：加载、切块（定长 / 按标题）、索引、内存检索器、BM25/RRF、问答链
.data/            本地索引缓存（vectors.gob / idx-*.gob，已被 gitignore）
```
